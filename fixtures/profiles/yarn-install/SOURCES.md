# P03 sources

- Original authored capture recipe and tiny projects: this directory, MIT repository license.
  No donor parser/code/fixture copied; source transformations: none. Generated Yarn locks and
  npm tooling locks retained; downloaded package implementations are not committed.
- Local tooling distributions: public `https://registry.npmjs.org/yarn` at **1.22.22** and
  `https://registry.npmjs.org/@yarnpkg%2fcli-dist` at **4.10.3**, BSD-2-Clause.
  `classic-tooling-lock.json` / `berry-tooling-lock.json` pin resolved tarball URLs and
  SHA-512 integrity; tooling install commands/exits are documented by recipe and native logs.
- Tiny public graph: **chalk 4.1.2**, MIT, fetched by original bare Yarn install.
  Generated project Yarn locks pin dependency resolutions/checksums. No large application
  builds, global installs, private registries, npm/pnpm corpus captures or copied donor code.
- `cases.json`: original command, argv, pinned executable path/version, platform, cwd,
  observed termination, complete pipe boundary, unknown presentation and raw SHA-256.
  LF-ended bytes use raw files; no-LF bytes use inline output without adding LF.
- `capture-attempts.json`: original failed attempts archived losslessly as inline UTF-8
  output plus original SHA-256; their schema remains `hugr-lean/native-cases/1`.
  It is an archive, not a reserved common C02 receipt; no `provenance.record` indirection.
- `capture-context.json`: capture root, Node/platform and final recipe hash. Recipe evolved
  during recovery; this hash identifies final reproduction recipe, not a historical attestation
   of every earlier process. Raw hashes attest stored bytes, not an external notarization.

## Supplement sources and transformations

- Authored `supplement.py`, `supplement-receipt.py`, `supplement-controls.mjs` and tiny
  private manifests/configs: repository MIT license, no donor code copied.
- Public version metadata captured verbatim from `https://registry.npmjs.org/inflight/1.0.6`,
  `/once/1.4.0`, `/wrappy/1.0.2`; retained as `supplement-*-metadata.json`, SHA-256 in receipt.
  All three packages ISC. Metadata supplies native `deprecated` field for inflight, graph,
  resolved tarball URLs and SHA-512 SRI. No package implementation copied into repository.
- Tool distribution versions/licenses unchanged: Yarn 1.22.22 / cli-dist 4.10.3, BSD-2-Clause.
  `supplement-projects/*/tool/package-lock.json` derives conventional local npm-ci package keys
  from exact historical pinned entries; original tooling locks/logs remain unchanged.
- `supplement-projects/*/project/yarn.lock` generated by actual recorded Yarn installers:
  inflight 1.0.6 -> once 1.4.0 + wrappy 1.0.2; once -> wrappy. Classic stores tarball/SRI,
  Berry stores native resolution/archive checksum; public metadata retains SRI for both.
- `supplement-receipts.json`: execution/source/artifact hashes, Node/npm/platform, actual
  launcher/executable, separate argv/env, native exit and EOF; `cases` binds current reader.
  `bindingProducer` records separate post-capture binding script, not rewritten process history.
- Tool/version logs are declared once in `cases.json` string `archives`; four install outputs
  are case inputs only. Registry metadata is supporting evidence, not Yarn reporter text.
- Registry version metadata includes upstream source commits (`gitHead`) where supplied;
  byte hashes pin captured documents. Raw metadata and generated locks unmodified.
