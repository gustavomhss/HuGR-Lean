## Boundary and EOF

Every native case uses stdout `PIPE` with stderr `STDOUT`, no PTY, raw bytes, no trimming,
color stripping, newline normalization or synthetic replacement. This is a complete
**combined-pipe** boundary, not separate authenticated stdout/stderr or OpenCode host capture.
Plugin source explicitly writes stdout; merged native bytes do not attribute each row.
Timeout would retain bytes with incomplete/timeout metadata, never claim complete success.
The recorded run has 38 exited/complete cases; 3 empty outputs and 35 LF-ended outputs.
No native no-LF output was observed or fabricated. UTF-8 bytes are measured separately
from character counts; any future source spans must use UTF-16 indices.

`cases.json` uses `hugr-lean/native-cases/1`; each case has **file only**, never both file
and inline output. All statuses are `passthrough` as pending-policy expectations, not
claims of tested public-filter support. Exact original files are the expected evidence.
No reduction golden is presented as approved output.

## Verification reach

`verify.py` checks explicit case IDs, exit/byte observations, manifest/receipt correspondence,
raw/source/collector/metadata/install hashes, EOF and lock integrity. Positive controls see
real differences, syntax diagnostics, Unicode byte expansion and producer collision.
Three destructive probes run in memory: delete plugin header, delete final LF, alter first
byte while keeping length. Each must be rejected; original control is checked afterward.
Native files are never mutated. This checks artifact preservation, not runtime filter behavior.

Framing error to avoid: **captured passthrough is not completed mandatory reduction coverage**.

unmatched check outputs are identical, so success does not prove a file was formatted.
